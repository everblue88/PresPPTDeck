# 方案评审模板

> **适用场景：** 技术方案评审、产品方案评审、业务方案评审、项目立项评审
> **推荐风格：** 科技蓝白 或 金融黑金
> **推荐页数：** 10-12页（15-20分钟）

---

## 模板说明

方案评审的核心是**让评审委员会认同方案可行、风险可控、值得投入资源**。汇报对象通常是技术/业务负责人组成的评审团，关注点是方案合理性、技术可行性、风险可控性、资源投入产出比。

---

## 页面结构

### P1 — 封面
- **标题：** [方案名称] — 方案评审报告
- **副标题：** 一句话方案概述
- **内容：** 提案人 + 提案日期
- **视觉建议：** 简洁专业风格

---

### P2 — 目录
- **核心观点：** 汇报结构导航
- **内容：**
  1. 背景与问题
  2. 方案目标
  3. 方案设计
  4. 方案对比
  5. 实施计划
  6. 风险评估
  7. 资源需求
- **视觉建议：** 图标卡片网格

---

### P3 — 背景与问题
- **核心观点：** 为什么需要这个方案？不解决会怎样？
- **示例标题：** "现有系统处理能力已接近瓶颈，预计Q3将无法支撑业务增长"
- **副标题：** 问题的紧迫性决定了方案的优先级
- **内容要点：**
  1. 当前状况（数据和事实）
  2. 核心问题（最需要解决的3个问题）
  3. 不解决的后果（业务影响、技术债务、成本增加）
  4. 解决后的收益（业务价值）
- **推荐视觉模型：** 数据冲击型开场（关键数字放大） + Before/After
- **所需素材：** 当前系统数据、业务增长预测

---

### P4 — 方案目标
- **核心观点：** 方案要达成什么目标
- **示例标题：** "目标：在3个月内将系统处理能力提升3倍，同时降低运维成本30%"
- **副标题：** 目标要SMART——具体、可衡量、可达成、相关、有时限
- **内容要点：**
  1. 核心目标（量化）
  2. 成功标准（如何衡量方案是否成功）
  3. 方案范围（做什么，不做什么）
  4. 约束条件（时间、预算、技术栈限制）
- **推荐视觉模型：** 指标卡片（目标拆解）
- **所需素材：** 目标数据

---

### P5 — 方案设计
- **核心观点：** 方案的核心设计思路和架构
- **示例标题：** "采用微服务+事件驱动架构，实现高可用、可扩展、低耦合的系统"
- **副标题：** 设计思路决定方案的优劣
- **内容要点：**
  1. 整体架构（文字描述+架构图描述）
  2. 核心设计决策（为什么这样设计）
  3. 关键技术选型（用什么技术，为什么）
  4. 设计原则（可扩展、高可用、低成本...）
- **推荐视觉模型：** 分层模型（架构图） 或 流程图
- **所需素材：** 架构设计图、技术选型对比

---

### P6 — 核心模块详解
- **核心观点：** 方案的3个核心模块如何解决问题
- **示例标题：** "3个核心模块对应3个关键问题，每个模块都有明确的职责和边界"
- **副标题：** 模块化设计 = 可维护 + 可扩展
- **内容要点：**
  1. 模块1：[名称] — 解决什么问题 — 如何实现
  2. 模块2：[名称] — 解决什么问题 — 如何实现
  3. 模块3：[名称] — 解决什么问题 — 如何实现
- **推荐视觉模型：** 图标卡片 或 分层模型
- **所需素材：** 模块设计详情

---

### P7 — 方案对比
- **核心观点：** 为什么选择这个方案而不是其他方案
- **示例标题：** "对比了3种方案，推荐方案A——综合得分最高，风险最低"
- **副标题：** 有对比才有说服力
- **内容要点：**
  1. 方案A（推荐）：优势、劣势、适用场景
  2. 方案B（备选）：优势、劣势、适用场景
  3. 方案C（放弃）：为什么放弃
  4. 对比维度：技术复杂度、实施周期、成本、风险、可扩展性
- **推荐视觉模型：** 对比表/矩阵 或 雷达图（多维度对比）
- **所需素材：** 方案对比数据

---

### P8 — 实施计划
- **核心观点：** 如何落地这个方案
- **示例标题：** "分3个阶段实施，总工期12周，关键里程碑已明确"
- **副标题：** 可行的计划 = 合理的时间 + 清晰的职责 + 可控的风险
- **内容要点：**
  1. 实施阶段（Phase 1/2/3）
  2. 每个阶段的目标和产出
  3. 关键里程碑和时间节点
  4. 团队分工和职责
- **推荐视觉模型：** 时间轴/甘特图
- **所需素材：** 实施计划详情

---

### P9 — 风险评估与应对
- **核心观点：** 识别了关键风险，每个风险都有应对方案
- **示例标题：** "识别了5个风险点，其中2个高风险已制定详细应对预案"
- **副标题：** 展示风险意识，比假装没有风险更可信
- **内容要点：**
  1. 高风险1：描述 + 概率 + 影响 + 应对措施 + 触发条件
  2. 高风险2：同上
  3. 中风险：同上
  4. 风险监控机制（如何及时发现和升级）
- **推荐视觉模型：** 风险矩阵（概率×影响） 或 分级列表
- **所需素材：** 风险清单

---

### P10 — 资源需求与ROI
- **核心观点：** 需要什么资源，能带来什么回报
- **示例标题：** "投入XX万+10人×3个月，预计12个月内收回投资，ROI达XX%"
- **副标题：** 让决策者看到投入产出
- **内容要点：**
  1. 资源需求（人力、预算、时间、基础设施）
  2. 投入产出分析（投入多少，产出什么）
  3. 回报周期（什么时候开始产生价值）
  4. 非量化收益（技术积累、团队成长、战略价值）
- **推荐视觉模型：** Dashboard（资源指标卡） + 柱状图（投入产出）
- **所需素材：** 预算数据、人力计划

---

### P11 — 总结与建议
- **核心观点：** 复述最重要的信息，明确请求决策
- **内容：**
  1. 问题紧迫性（为什么现在必须做）
  2. 方案优势（为什么推荐这个方案）
  3. 投入产出（值得投入的理由）
- **推荐视觉模型：** 图标卡片（3个卡片）
- **行动号召：** "请求批准方案并授权启动实施"

---

### P12 — 感谢页
- **内容：** 感谢评审 + 联系方式
- **视觉建议：** 简洁文字

---

## 使用提示

1. **方案对比要客观：** 不要只展示推荐方案的优势，隐藏劣势
2. **风险要诚实：** 评审团最怕的是"没有风险"的方案
3. **ROI要务实：** 不要过度承诺，留有余地
4. **实施计划要可执行：** 不要画"大饼"，展示具体的时间和人
5. **准备被挑战：** 评审团一定会质疑，提前准备应对
