# Story Architect — 商业故事构建引擎

## 定位

> **将 Story Brief 转化为完整的商业故事和页面规划。**

## 核心能力

1. **Executive Story Framework**：6段式商业故事构建
2. **Slide Type Recognition**：自动识别内容适合的页面类型
3. **Slide Planner**：完整的分页规划

---

## 一、Executive Story Framework（6段式）

从 V0.2 的 WHY→WHAT→HOW→RESULT→NEXT（5段式）升级为 **6段式商业故事框架**，更适合管理层汇报。

```
1. 背景变化（Context Shift）
   ↓
2. 核心问题（Core Challenge）
   ↓
3. 战略机会（Strategic Opportunity）
   ↓
4. 解决方案（Solution）
   ↓
5. 核心价值（Business Value）
   ↓
6. 下一阶段（Next Phase）
```

---

### 段1：背景变化（Context Shift）

**回答：** 为什么现在必须做？

**引导问题：**
- 外部环境发生了什么变化？（行业、技术、政策、竞争）
- 内部发生了什么变化？（战略、组织、能力）
- 如果现在不做，会有什么后果？

**关键原则：** 让听众在30秒内感受到"变化"和"紧迫感"。

**表达方式：**
- 数据冲击型："市场规模年增40%，但我们的份额在下降"
- 趋势洞察型："AI正在重塑行业格局，窗口期只有12个月"
- 危机驱动型："如果不做改变，2年内将失去竞争力"

---

### 段2：核心问题（Core Challenge）

**回答：** 目前面临的核心挑战是什么？

**引导问题：**
- 最核心的1-2个问题是什么？
- 这些问题造成了什么影响？
- 为什么之前没有解决？

**关键原则：** 问题要具体，不能泛泛而谈。用数据量化问题。

**示例：**
- ❌ "我们的效率不够高"
- ✅ "客服团队处理一个客户咨询平均需要15分钟，是行业平均水平的3倍"

---

### 段3：战略机会（Strategic Opportunity）

**回答：** 为什么这是一个值得抓住的机会？

**引导问题：**
- 解决这个问题能带来什么战略价值？
- 市场上有哪些成功案例？
- 为什么是我们？为什么是现在？

**关键原则：** 从"问题"转向"机会"，建立正向叙事。

**表达方式：**
- 市场机会：市场规模、增长空间
- 竞争优势：我们的独特优势
- 时机窗口：为什么现在是最好时机

---

### 段4：解决方案（Solution）

**回答：** 我们准备怎么做？

**引导问题：**
- 核心策略是什么？（不超过3个）
- 关键举措是什么？
- 与竞品/替代方案的区别是什么？

**关键原则：** 策略聚焦，不超过3个。每个策略有明确的"做什么"和"为什么这样做"。

**结构：**
```
策略1：[名称] → 做什么 → 解决什么问题
策略2：[名称] → 做什么 → 解决什么问题
策略3：[名称] → 做什么 → 解决什么问题
```

---

### 段5：核心价值（Business Value）

**回答：** 带来什么业务结果？

**引导问题：**
- 效率提升多少？
- 成本降低多少？
- 收入增长多少？
- 用户体验改善多少？
- 对长期竞争力的影响？

**关键原则：** 用数据说话，价值量化。区分"已实现"和"预期"。

**表达方式：**
- Dashboard：核心指标一览
- Before/After：改造前后的对比
- 价值公式：投入→产出→价值

---

### 段6：下一阶段（Next Phase）

**回答：** 未来如何扩大？

**引导问题：**
- 下一步做什么？什么时候做？
- 需要什么资源？
- 目标是什么？如何衡量成功？

**关键原则：** 规划具体，有明确的时间节点和里程碑。展示信心但不盲目。

## 二、Slide Type Recognition（页面类型自动识别）

### 核心能力

基于内容语义，自动判断每页应该用什么视觉模式表达。

### 识别规则

| 内容特征 | 自动识别为 | Pattern |
|---------|-----------|---------|
| 整体目标/核心结论 | 封面/摘要 | cover / summary |
| 背景变化、行业趋势 | 数据冲击 | dashboard |
| 问题分析、挑战 | 对比（现状vs理想） | comparison |
| 战略框架、体系 | 分层模型/金字塔 | framework / pyramid |
| 三大方向、核心策略 | 三角模型/卡片 | framework / case_card |
| 流程、步骤 | 流程图 | process |
| 时间规划、里程碑 | 时间轴/路线图 | timeline / roadmap |
| 改造前后 | Before/After | before_after |
| 数据结果 | 指标卡/Dashboard | dashboard |
| 方案对比 | 对比表 | comparison |
| 组织结构 | 组织架构图 | organization |
| 技术方案 | 技术架构图 | architecture |
| 竞争力分析 | 矩阵/四象限 | matrix |
| 增长逻辑 | 飞轮 | flywheel |
| 成功案例 | 案例卡片 | case_card |

### 识别流程

```
内容输入 → 语义分析 → 模式匹配 → 推荐Pattern（含备选）
```

每页推荐 **1个首选Pattern + 1个备选Pattern**。

## 三、Slide Planner（页面规划）

### 规划原则

1. **一页一观点：** 每页只表达一个核心观点
2. **逻辑流：** 页面之间要有明确的递进关系
3. **节奏感：** 数据页和故事页交替，避免连续数据页
4. **时间适配：** 根据汇报时长自动调整页数

### 页数时间对照

| 汇报时长 | 推荐页数 | 结构分配 |
|---------|---------|---------|
| 5分钟 | 5-7页 | 封面+3核心+结尾 |
| 10分钟 | 8-10页 | 封面+目录+5核心+结尾 |
| 15分钟 | 10-14页 | 完整6段式 |
| 30分钟 | 15-20页 | 每段2-3页展开 |
| 45分钟+ | 20-25页 | 含附录和深度分析 |

### 每页定义

```
【页面编号】P1
【页面标题】有观点的标题（不是"XX介绍"）
【副标题】为什么重要
【内容概要】用什么证明
【推荐Pattern】首选 + 备选
【内容来源】用户提供 / AI补充
```

## 输出格式：Story Architecture

### 完整输出（含三级信息结构）

```
【Story Architecture — 完整汇报架构】

## 故事线（6段式）
1. 背景变化：[一句话]
2. 核心问题：[一句话]
3. 战略机会：[一句话]
4. 解决方案：[一句话]
5. 核心价值：[一句话]
6. 下一阶段：[一句话]

## Story Framework（三级信息结构）

P1 封面
  标题（Title）：[我要讲什么？— 有观点的标题]
  副标题（Subtitle）：[从什么角度讲？]
  核心逻辑（Logic）：[这一页想让听众记住什么？]

P2 执行摘要
  标题（Title）：[一句话总结整个汇报]
  副标题（Subtitle）：[补充视角]
  核心逻辑（Logic）：[听众看完这一页应该得到什么信息]

P3 [页面主题]
  标题（Title）：[有观点的标题]
  副标题（Subtitle）：[角度/范围/限定]
  核心逻辑（Logic）：[这一页具体想让听众记住什么？]
  Pattern：[首选] / [备选]
  来源：[用户提供/AI补充]

...

PN 结尾
  标题（Title）：[感谢/行动号召]
  副标题（Subtitle）：[核心信息重申]
  核心逻辑（Logic）：[听众应该做什么]
  Pattern：cover
  来源：AI整合

## Pattern使用统计
- cover: 2次
- dashboard: 3次
- before_after: 1次
- ...
```

### 三级信息结构说明

| 层级 | 名称 | 回答 | 要求 |
|------|------|------|------|
| Level 1 | Title | 我要讲什么？ | 有观点的标题，不是中性描述 |
| Level 2 | Subtitle | 从什么角度讲？ | 补充视角、范围或限定 |
| Level 3 | Logic | 想让听众记住什么？ | 一句话，完整表达核心信息 |

**示例：**
```
❌ 弱表达：
  标题：AI赋能产研
  副标题：提升团队研发效率

✅ 强表达：
  标题：AI赋能产研：从效率工具走向生产模式重塑
  副标题：从个人提效、专家知识沉淀到AI产品化，逐步形成新的产研体系
  核心逻辑：AI的价值不应停留在"帮员工做得更快"，而应该进一步沉淀业务知识、
  重构工作流程，并最终形成可持续的产品和业务价值。
```

## 过渡引导

完成 Story Architecture 后，自动进入 Per-Page Content Enrichment：

> "故事线和页面结构已经规划完成。接下来，我会对每一页进行内容饱满度检查和补全，确保每一页都有足够的内容密度。"

**参考：** `core/content_expansion.md`（Per-Page Content Enrichment 章节）

然后进入 Per-Page Content Enrichment → Full Content Approval → 用户确认后进入 Pattern Selector（CREATE阶段）。
