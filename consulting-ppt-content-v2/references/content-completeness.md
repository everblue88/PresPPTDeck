# 内容完整性与主动补全

完整性指听众作出目标判断所需的信息是否到位，而非页数或每页信息单元数量。先列内容义务，再决定页面。逐项标记`已证实/可用外部研究补足/需客户补数/待验证假设/不适用及原因`。

| 汇报目的 | 必须回答的问题 |
|---|---|
| 立项或投资 | 基线与机会、目标人群/流程、推荐与备选、选择标准、成本资源、价值及其证据、风险、实施与明确请求 |
| 战略或商业方案 | 外部变化、内部差距、目标、路径比较、能力约束、价值机制、执行条件、风险与里程碑 |
| 项目进度 | 目标和计划、实际与偏差、原因、影响、预测、纠偏、责任及需升级的决定 |
| 经营汇报 | 指标口径、目标与实际、驱动因素、可归因行动、问题、预测及资源请求 |
| 述职 | 职责目标、实际成果、本人贡献、证据、复盘和后续承诺 |
| 成果汇报/报奖 | 原始问题、完成范围、解决机制、相对原做法的差异、成果及评价口径、可归因贡献、复用条件与局限 |
| 销售/客户提案 | 客户任务与痛点、方案适配、价值机制、可比案例、交付边界、差异、客户异议与下一步 |
| 知识分享 | 听众已有认知、核心概念、机制、例证、适用边界及可带走的做法 |

场景混合时先确定主目的，吸收副目的所必需的问题。时长限制可改变正文与附录的分配，不能删除高影响依据。

## 补全顺序

1. 按是否会改变听众对核心信息的理解、信任、评价或行动给缺口排序；立项场景再考虑“做不做、选哪条路、投入多少、何时做”。
2. 先深挖已有材料中的流程、对比、时间线、用户反馈和隐含约束。
3. 只为外部可验证缺口定向研究行业机制、标准、竞品、案例和方法。
4. 用问题树、流程、价值树或选项矩阵补逻辑；分析推导不能伪装成实测结果。
5. 缺客户专有数据时先寻找可获取的替代证据，例如流程记录、上线清单、验收材料、工单、原始反馈、前后样本；无法取得时明确口径和获取任务。试点/对照仅在适合用户目的时提出，不替代当前稿件应写的内容。

逐个关键判断检查**覆盖度**和**可信度**：问题是否回答；证据是直接还是类比；替代解释和最强反论是什么。只有机制时可以解释方案如何工作、为何值得考虑，但不能写成客户已取得成效。

交付前做标题串读、逐页证据核对和反方审阅。不要为“每页 ≥8 个单元”或低待填比例添加无关内容。高影响缺口仍在时，收窄结论并给补数任务。

## 四种缺口要分别处理

| 缺口 | 识别信号 | 应补的实际内容 |
|---|---|---|
| 主题覆盖不足 | 讲了功能，却没说使用对象、业务问题、差异或价值 | 按本次目的补出缺失的问题和对应章节 |
| 分析不足 | 有事实与口号，却没解释原因、机制、比较或取舍 | 从材料建立流程、因果链、对比或价值树，写出推导与限制 |
| 证据不足 | 结论超出材料，数字无口径，案例不能类比 | 核实来源、补可比证据、收窄结论；客户数据留明确任务 |
| 表达不足 | 只有大纲、单词、页面字段或重复句 | 写成实际页面文案，补“为什么重要/意味着什么”，删重复 |

缺口表不要只有状态，增加：`待回答问题｜影响的主张｜已有材料｜拟补内容｜补全方式｜落在哪页｜残余缺口`。一个来源可服务多页，同一论据不能通过反复改写制造丰富度。

## 主动补全循环

先在内部完成一版“最小完整故事”，找出会使听众困惑、不相信或无法行动的断点。逐个断点选择材料深挖、公开研究、分析推导或客户补数，将得到的内容真正写回页面，再复评标题和论点树。重要新证据与初始答案冲突时更新答案。

用户不给足信息时也应交出尽可能完整的稿件：已知事实具体写；机制与方法清楚展开；案例说明可借鉴点；未知内部数值保留局部缺口。不能把整个交付缩成一张“请提供资料”清单。进一步研究只增加相似背景、无法改变核心判断时停止检索。

## 内容丰富度的五项检查

| 维度 | 合格的可观察表现 | 不合格时怎样补 |
|---|---|---|
| 目的覆盖 | 听众达到目标所需的主要问题均被回答 | 补遗漏的问题及页面，不盲目扩页 |
| 分析深度 | 核心观点有机制、比较或推导，并说明适用条件 | 补“为什么”“相对什么”“在哪些条件成立” |
| 证据质量 | 重要事实可追溯，内部与外部边界清楚，证据强度匹配措辞 | 定向补证据或降低主张强度 |
| 页面实质 | 有可直接使用的正文；各信息点承担互补作用 | 将空泛词和提纲写成具体内容，删除同义重复 |
| 目的闭环 | 结尾使听众形成所需认知、评价或可执行行动 | 按原目的补收束；不一律加预算审批与试点 |

每项用`充分/需补强/关键缺失`评价，并列出具体问题及处理结果。不用总分掩盖关键证据缺失，也不以“每页硬支撑比例”判定真假。先修当前可修的问题，再交付剩余限制；不能为通过检查编造数据。

## 例：把“提升研发效率”补成内容

先限定对象与环节：需求澄清、代码检索、测试生成还是缺陷定位？若材料只写“上线知识助手”，可先补工作流变化、知识来源、引用与审核机制、适用任务及不适用任务；再查同行如何评价同类任务，说明可借鉴的测量方法。只有客户工时与质量对照到位后才写提升幅度。这样即使收益数字未知，页面仍有机制、边界、案例启发和可执行的测量口径。
