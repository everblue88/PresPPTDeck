# Visual Rules — 视觉设计规则

> **PresPPTDeck V0.3 核心质量保障机制。** 每页PPT必须满足以下规则。

---

## Rule 1：页面丰富度（覆盖率 ≥60%）

### 规则

每页PPT的内容覆盖率必须 ≥60%。如果低于60%，返回 Content Expansion 重新补全。

### 覆盖率计算公式

```
覆盖率 = 已填充内容区域 / 页面可用内容区域 × 100%
```

### 内容区域定义

- 标题区：页面上方15%
- 内容区：页面中间70%
- 注释区：页面下方15%

### 判定标准

| 覆盖率 | 判定 | 处理 |
|--------|------|------|
| ≥80% | 优秀 | 通过 |
| 60%-79% | 合格 | 通过，可优化 |
| 40%-59% | 不足 | 返回 Content Expansion |
| <40% | 严重不足 | 重新设计页面结构 |

### 提升覆盖率的方法

- 添加数据支撑（指标卡、图表）
- 添加案例说明（客户案例、行业对标）
- 添加视觉元素（图标、示意图、对比图）
- 拆分或合并页面（如果一页确实内容太少，考虑合并到相邻页面）

## Rule 2：禁止文字堆叠（连续 ≥3 Bullet 必须转换）

### 规则

连续**3条及以上**的纯文字Bullet列表，**必须**转换为以下形式之一：

| 转换方式 | 适用场景 | 示例 |
|---------|---------|------|
| 图标卡片 | 并列要点 | 3个核心策略 → 3张图标卡片 |
| 流程图 | 步骤/流程 | 3步流程 → 流程图 |
| 时间轴 | 时间节点 | 3个里程碑 → 时间轴 |
| 对比表 | 方案对比 | 3个方案 → 对比表 |
| 分层模型 | 层级关系 | 基础→进阶→高级 → 金字塔 |
| 数据指标卡 | 数据结果 | 3个KPI → 3个指标卡 |
| Before/After | 改造前后 | 改造前3点 vs 改造后3点 |
| 三角模型 | 三个方向 | 3个支柱 → 三角架构 |
| 飞轮模型 | 增长循环 | 3个环节 → 飞轮 |
| Roadmap | 分阶段规划 | 3个阶段 → 路线图 |

### 转换检查

- 每页生成前，检查连续Bullet数量
- ≥3条 → 触发 Pattern Selector 自动选择最佳视觉模式
- 如果无法找到合适的Pattern，考虑拆分页面

### 示例

**❌ 错误：**
```
AI赋能成果：
• 运营剪辑效率提升50%
• 业务专家知识完成沉淀
• 自动化流程覆盖3个场景
• AI金融产品已启动探索
• 团队AI能力显著提升
```

**✅ 优化（卡片式）：**
```
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│  🤖 效率提升  │ │  📚 知识沉淀  │ │  ⚡ 自动化   │
│  剪辑效率+50% │ │  专家知识体系 │ │  3场景覆盖   │
└──────────────┘ └──────────────┘ └──────────────┘
```

## Rule 3：页面视觉评分（100分制）

### 评分维度

| 维度 | 分值 | 评分标准 |
|------|------|---------|
| 结构清晰 | 30分 | 标题有观点(10) + 信息层级清晰(10) + 视觉引导线明确(10) |
| 视觉表达 | 30分 | 使用了合适的图形/图表(10) + 配色协调(10) + 元素对齐(10) |
| 内容密度 | 20分 | 信息量适中(10) + 无冗余内容(10) |
| 风格统一 | 20分 | 与整体风格一致(10) + 字体/字号统一(10) |

### 评分标准

| 分数 | 等级 | 处理 |
|------|------|------|
| 90-100 | 优秀 | 通过 |
| 80-89 | 良好 | 通过 |
| 70-79 | 一般 | 需优化，标注改进点 |
| 60-69 | 较差 | 重新设计 |
| <60 | 不合格 | 返回重做 |

**最低通过线：80分。**

### 评分检查清单

```
□ 结构清晰（30分）
  □ 标题是否表达了观点？（不是"XX介绍"）(10分)
  □ 信息是否有清晰的层级？（标题→副标题→正文）(10分)
  □ 读者视线是否有明确的流动方向？(10分)

□ 视觉表达（30分）
  □ 是否使用了合适的图形/图表/卡片？(10分)
  □ 配色是否协调？是否使用了风格规定的配色？(10分)
  □ 元素是否对齐？间距是否一致？(10分)

□ 内容密度（20分）
  □ 信息量是否适中？（不太空也不太满）(10分)
  □ 是否有可以删减的冗余内容？(10分)

□ 风格统一（20分）
  □ 与整体设计风格是否一致？(10分)
  □ 字体、字号、颜色是否统一？(10分)
```

## Rule 4：其他视觉规则

### 4.1 标题规则

- 标题必须表达观点，不能是"XX介绍"、"XX分析"这类中性标题
- 标题长度：8-20字最佳
- 标题字体大小：28pt-36pt
- 示例：❌ "用户数据分析" → ✅ "用户活跃度同比提升35%"

### 4.2 配色规则

- 每页不超过4种颜色（不含黑白灰）
- 强调色只用于关键数据或行动号召，不超过页面面积的10%
- 图表配色遵循风格系统的配色方案

### 4.3 字体规则

- 每页不超过3种字号
- 标题 > 副标题 > 正文 > 注释
- 数据数字使用加粗

### 4.4 图标规则

- 同一页面内图标风格统一
- 图标大小一致
- 图标颜色与风格配色一致

### 4.5 数据规则

- 所有数据标注来源（用户提供 / 行业参考 / 需验证）
- 数据对比必须有基准（同比/环比/行业平均）
- 大数字展示时，配合趋势箭头（↑↓→）

## Rule 4：禁止空洞页面

### 规则

以下三种空洞页面模式**必须重新设计**：

### 空洞模式A：只有标题+三句话

```
❌ 示例：
AI赋能
提高效率
创造价值
```

**问题：** 没有信息量，没有数据支撑，没有案例。

**处理：** 返回 Content Expansion，补充数据、案例、行业对标。

### 空洞模式B：纯列表（>3条连续Bullet）

```
❌ 示例：
优化APP
优化数据
优化AI
优化流程
```

**问题：** 只有动作没有逻辑，听众无法理解"为什么"和"怎么做"。

**处理：** 转换为能力模型、Roadmap、飞轮模型等图形化表达。

### 空洞模式C：只有定性描述，无量化数据

```
❌ 示例：
效率提升了
客户满意度提高了
```

**问题：** 没有具体数据，无法说服听众。

**处理：** 补充具体数据或行业对标。如果没有精确数据，使用行业参考范围并标注`[行业数据]`。

### 空洞页面检测流程

```
每页生成后
    ↓
检查是否命中空洞模式
    ↓
┌───┴───┐
↓       ↓
未命中   命中
↓       ↓
通过   返回 Content Expansion
        ↓
      重新生成
        ↓
      再次检查
```
