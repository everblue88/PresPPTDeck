# 定向研究与证据台账

研究前先问：“没有这条事实，哪项判断会失去支撑？”优先客户原始记录、财务/运营数据、项目结果与用户反馈。公开资料只补行业趋势、技术事实、政策、可比做法、评价方法或案例；若用户限定只用给定材料，遵守边界。

优先原始、权威、可定位的来源。关键外部事实记录发布/统计时间、样本场景、指标定义、链接和适用范围。案例写清做法、公开结果、与客户的相似及差异、可迁移机制与不可迁移数值。来源冲突时检查时间、地域、定义与分母；仍有冲突则保留分歧。

| 证据类型 | 允许的措辞边界 |
|---|---|
| 客户核实事实 | 可说“当前流程/实测显示”，不可超出样本或时间推及全公司 |
| 外部核实事实 | 可说“公开案例显示”，不可说“客户也将达到同等结果” |
| 分析推导 | 写明前提与“可能”，不可写成已观察到的结果 |
| 待验证假设 | 说明如何取得证据，不写“已经证明”；验证方式按场景选择 |
| 建议行动 | 说明依据与条件；有必要时给退出门槛，不冒充事实 |

## 最小证据台账

| 判断 ID/页码 | 需要证明 | 证据 ID 与原始定位 | 类型/时间/口径 | 支持范围 | 残余缺口及影响 |
|---|---|---|---|---|---|

重要判断必须能回溯证据；资料再多，若不能服务关键判断就删去。对高影响内部缺口给任务单：缺什么、分母和时间窗、数据系统或责任团队、获取方法、期限、取不到时须降级的结论。不能留下裸`【待填】`。在页面正文附近标证据 ID，末尾统一列来源。

## 将外部研究转成客户内容

材料缺少行业背景、成熟做法或论据时，主动研究可填补这些缺口的原始资料；不要求客户先指出搜什么。检索同时关注支持证据、失败条件与替代做法，不只搜证明初始结论的词。没有联网能力或用户限制检索时明确边界，不凭记忆编造引用。

一条外部资料进入稿件前，回答：它解决哪个听众问题？与客户的业务、流程、规模和约束是否可比？支持机制、选择、方法还是数值结果？与现有证据相比新增了什么？

对有价值的案例写成：`案例对象与背景→采取的具体做法→来源实际披露的结果→与客户的相同/不同→本客户可借鉴的动作与条件`。再融入对应页面的论据和推导，不将搜索摘要原样拼成“行业案例页”。只披露做法而无结果的来源，应明确“做法参考”，不可称为已证实的最佳效果。

数字可比性不足时，可以借鉴测量维度与流程，不迁移提升幅度。外部研究不足以证明客户创新的“首创/领先”，应改写为可证实的差异；内部成果可用正式记录、原始反馈或具体前后案例支持，不强制所有论据量化。
